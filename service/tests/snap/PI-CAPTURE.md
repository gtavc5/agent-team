# Pi recordings

Read the `source` in the JSONL header before using a frame. A Pi v3 session is not an RPC trace, and `stream.jsonl` is the server's **projection**: it cannot tell us which RPC events preceded it. Do not reconstruct RPC deltas from either.

- **Live turns:** `npm run capture -- pi basic-turn` (or `image-prompt`, `interrupt-abort`, `single-queue-order`, `tools-bash-edit`, `extension-ui-dialog`, `antigravity-acp-turn`). Each invocation spends account quota. Do not loop. Only reviewed fixture prompts are accepted, in a disposable workspace without context files. The dialog fixture explicitly loads a confirmation extension; the ACP fixture requires `PI_ACP_EXTENSION` pointing to the installed provider entry. Tool capture restricts reads and edits to the seeded file and bash to a fixed command. A per-user lock serializes capture plus cooldown; after a recorder crash check no capture is active before removing its stale lock.
- **Offline scenario:** `npm run capture -- pi scenario` runs the real deterministic WebSocket/Pi/subagents E2E with its local provider. A temporary tap observes the real subprocess stdin/stdout and child artifacts; its raw files are removed on exit. Foreground and async clips keep the observed sibling identities, notice and child results. `panel-tools-roundtrip` selects calls from three scenario turns; the replay substitutes the real Panel HTTP handler result at each call. `crash-and-restore` composes real scenario excerpts, withholding the receipt and user echo and injecting a process exit with two open tools. It does **not** claim the original process crashed.
- **Offline subagent widgets:** `npm run capture -- pi scenario-widgets` runs the same credential-free scenario and updates only `pi/messages/subagents-widgets.jsonl`. The recording header identifies both installed versions. The scenario inspects a running child, then releases both children while a separate parent prompt remains gated. The excerpt keeps the actual inspect reply and clear, one async widget per run state, and the parent settlement and subsequent native wake. The extraction redacts nested JSON strings and IDs, omits unrelated jobs and frames, and keeps relative timestamps. `pi-subagents-widgets.test.ts` replays the stdout through `PiRpcClient`; it asserts the raw machine protocol, not the Workspace's generic widget rendering.
- **Offline retry faults:** `npm run capture -- pi compaction-and-retry` injects a provider exception and replays the terminal assistant blocks from `tools-bash-edit` on retry, under the actual Pi CLI. The test splices the recorded overflow events into the retry interval and sets context tokens to null: missing telemetry must not become a fabricated token count. `npm run capture -- pi retry-failed` exhausts the retry budget. These are not natural provider outages.
- **Passive excerpts:** `npm run --silent capture -- pi extract SESSION.jsonl LINE` writes a two-line header and `get_messages` response to stdout. Select a one-based assistant or `subagent-notify` line from a Pi v3 transcript. It redacts before invoking a credential-free offline Pi, which restores that entry in a disposable session and serializes its actual RPC representation. Notices need not have a model. The three provider Read samples in `pi/messages/` preserve the argument keys and nulls.

Anonymization masks arbitrary strings (including text, signatures, errors, command bodies and paths) and pseudonymizes correlation IDs. Provider usage, recorded times and durations are intentionally retained. Unknown fields are anonymized too: recordings are not a byte-for-byte export of confidential sessions. Inspect every changed JSONL, **including object keys**, before committing. Run the snap, broadcast and privacy suites; update snapshots only after checking what changed. Captures against a live model need not produce identical replies on a new run. The checked-in tape, not the online model, is the reproducible input.
